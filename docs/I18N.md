# 国际化（i18n）

MVP 范围：**UI 三语**（简体 / 繁體 / English），**笔记正文暂不整站手翻**。

## 怎么切换

顶栏右侧**唯一**下拉（`LocaleSwitcher`：简体 / 繁體 / EN）。切换时会改写路径前缀：

- `/about/` ↔ `/zh-TW/about/` ↔ `/en/about/`
- `/web/foo` ↔ `/zh-TW/web/foo` ↔ `/en/web/foo`
- 若目标路径不存在，回落到该语言首页（`/`、`/zh-TW/`、`/en/`）

VitePress 顶栏 / Extra / 移动端屏自带语言入口已全部用 CSS 隐藏，避免双控件。

## 正文策略

VitePress 的 `rewrites` 是「源文件 → URL」**一对一**映射，无法把同一份 `web/foo.md` 同时挂到三个 locale URL。因此：

1. `en/index.md`、`zh-TW/index.md` 为独立落地页（`layout: home`，与简体同款 hero / pillars），说明正文以简体为主。
2. 配置加载时 `ensureLocaleContentAliases()` 用 `cpSync` 在 `en/`、`zh-TW/` 下为下列栏目生成**镜像副本**（不用符号链接）：

   `web` `ui` `engineering` `backend` `tech` `agent` `computer` `misc` `news` `about` `archive` `tags` `topics` `recent` `friends` `collect` `books` `talks` `suibi`

   原因：symlink 会被 Vite 解析到同一 realpath，`pageData.relativePath` 丢掉 `en/` / `zh-TW/` 前缀，导致除落地页外 UI 仍判成简体。

3. 生成物栏目（如 `books` / `collect` / `news`）在 `prebuild` 生成目录后才会镜像。

结果：`/en/web/...`、`/zh-TW/web/...` 与 `/web/...` 内容相同（简体 Markdown 副本）；壳（nav / footer / search / 主题文案）跟语言走。

改完栏目源文件后请**重启 `npm run dev`**，否则 locale 下副本不会更新。

## 如何加文案

1. 在 `website/.vitepress/i18n/messages.ts` 为 `zh-CN` / `zh-TW` / `en` 补字段。
2. 类型写在 `website/.vitepress/i18n/types.ts` 的 `MessageTree`。
3. Vue 内用 `useI18n().t('…')`；非 Vue（`theme/index.ts` DOM 脚本）用 `getUiText(lang)`。
4. nav / footer / search / notFound / outdateNotice 等走 `buildThemeConfig(locale, extras)`（`i18n/theme-config.ts`）。
5. en / zh-TW 的 **nav、sidebar link 必须带 locale 前缀**（绝对路径不会自动加；由 `localizeHref` 处理）。

## 相关文件

| 路径 | 作用 |
|------|------|
| `website/.vitepress/i18n/*` | 文案、themeConfig、栏目镜像 |
| `website/.vitepress/theme/i18n.ts` | `useI18n` / 路径工具 |
| `website/.vitepress/theme/LocaleSwitcher.vue` | 顶栏唯一下拉 |
| `website/en/index.md` / `website/zh-TW/index.md` | 各语言首页 |
| `website/.vitepress/config.ts` | `locales` + 调用镜像生成 |

## 限制

- 正文仍是简体；英文/繁体页是「本地化壳 + 简体内容」。
- 文章内写死的绝对路径（如 `/about/`）不会自动加 locale 前缀；themeConfig 导航已加。
- 未提交 `en/*`、`zh-TW/*` 栏目镜像时，需在加载 config / 跑 `vitepress` 时由 `ensureLocaleContentAliases` 创建；dev 改源后需重启。
